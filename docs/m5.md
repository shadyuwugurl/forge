# M5 optimizations (v0.7.1)

Bench: `cargo run --release -p forge-cli --example m5_bench`.
Parallelism: `FORGE_WORKERS` (default: ncpu). Byte budget 4GB caps
in-flight tensors; peak ≈ budget + largest tensor, never whole models.

## Micro A/B (release, Apple Silicon)

| op | before | after | speedup |
|---|---|---|---|
| unpack 1-bit 4M | 2.7ms | 0.2ms | 13x (byte LUTs) |
| unpack 2-bit 4M | 2.7ms | 0.4ms | 7x |
| unpack 4-bit 4M | 2.8ms | 0.8ms | 3.5x |
| pack 2/4-bit 4M | 2.3/3.5ms | 0.9/1.4ms | 2.5x (chunks_exact) |
| QuantGemv 1024x4096 2-bit | 7.7ms | 4.1ms | 1.9x (hoisted scale, 4x unroll) |
| tensor_f32 128MB mmap | 4.1ms | 4.0ms | — (already memcpy-bound; now guaranteed single memcpy) |

## CLI A/B, 260MB fixture (2x130M-param parents)

| op | serial (FORGE_WORKERS=1) | parallel | wall speedup | peak RSS |
|---|---|---|---|---|
| merge linear | 0.73s | 0.23s | 3.2x | 620MB → 1.1GB |
| quantize nanoquant | 6.23s | 0.77s | 8.1x (same user CPU: 5.8 vs 5.7s) | 304MB → 497MB |

Serial vs parallel outputs are bit-identical per tensor (md5 by name,
18 merge + 36 quant tensors, zero mismatches).

## Fixes found by M5 verification

- `LinearMerge::merge_tensors` override: `create_merge_op` builds
  `LinearMerge { models: vec![] }` for ~16 methods (linear, slerp,
  ties, dare, …) and the default trait method ignored inputs →
  `models[0]` panic on any linear-family merge. Now averages `inputs`
  (stored weights when counts match, else uniform; skips shape
  mismatches). Linear merge verified end to end on fixtures.

## New knobs

- `FORGE_WORKERS`: worker thread count for merge + quantize tensor loops.
